## 5단계 — 착시 연결 ✅

**왜 여기인가:** 게임의 이름값. 여기가 붙어야 '퍼즐'이 된다.

**착시가 성립하는 조건.** A 가 바닥, B 를 `z` 만큼 올렸을 때
`u = xb−xa`, `v = yb−ya` 라 하면 `|u−z| + |v−z| = 1`. 정수해는 둘뿐이다.

| B 의 위치 | 높이 | 결과 |
|---|---|---|
| 대각선에서 한 칸 벗어난 자리 (`u = v±1`) | `z = min(u,v)` | 나란히 선다 → **잇는 축** |
| 대각선 위 (`u = v`) | `z = u` | 정확히 포개진다 → **덮는 축** |

- [x] **겹친 후보 중 실제로 보이는 것만 길로 치기** — `z` 최대 하나만 남긴다
- [x] `pickAt` 을 부르지 않고 같은 규칙을 스냅샷 위에 다시 세움 (순수성 유지)
- [x] 보이지 않는 칸은 목적지로 누를 수 없음 (`pointer.hit` 이 이미 `pickAt` 결과)
- [x] **캐릭터를 덮는 높이 조절 차단** — 덮이면 화면에서 사라진다
- [x] 성향 지표 수집 — `inkSpent` / `illusionSteps` / `redraws`
- [x] 게임 내 표시 없음 — 그냥 이어져 보이기만 한다
- [x] **세운 판(벽)은 넣지 않기로 확정** — 「보류한 것」 참조
- [x] `AI_LOG.md` 5단계 기록

## 6단계 — AI 디렉터 ✅

**왜 마지막인가:** 디렉터가 조종할 손잡이(잉크 배급량, 지형, 목표 위치)가
먼저 존재해야 한다. **출품의 핵심.**

> AI는 레벨을 만들지 않는다. 플레이어를 읽고, 그 사람이 피하는 것을 만든다.

### 솔버는 길찾기가 아니다

이 단계의 핵심이고, 나머지가 전부 여기서 파생된다.

`findPath` 는 **이미 놓인 판** 위에서 길을 찾는다. 그런데 목표는 빈 바닥
칸이고 플레이어는 판을 **그려서** 간다. "풀리는가" 는 *배급량 이하의 칸을
그려서 목표에 닿는 방법이 존재하는가* 다. 그래프는 그대로 쓰고 간선에
비용만 붙인다.

```
화면 자리 s 로 한 칸 옮길 때
  s 에 보이는 판 칸이 있다        →  0        (이미 있는 길)
  s 가 비었고 기둥이 안 잡혀 있다  →  INK_COST (그려야 한다)
  기둥이 잡혀 있다                →  통과 불가
```

가중치가 0과 2뿐이라 **0-1 BFS** 한 번으로 최소 잉크가 나온다. 목표 칸도
빈 바닥이라 그리는 비용이 자연히 포함되고, 밟은 칸은 환급이 0 이므로
환급으로 이 값을 더 내릴 수 없다 — 진짜 하한이다.

**벽이 공짜로 나왔다.** 세 번째 줄의 결과다. 판 `(5,5)` 를 `z=3` 으로 올리면
화면에는 `(2,2)` 에 나타나지만 `occupied` 는 여전히 `(5,5)` 기둥을 잡고 있고
`pickAt(5,5)` 는 아무것도 찾지 못한다. **올린 판은 원래 자리에 통과 불가
구멍을 남긴다.** 5단계에서 벽을 안 넣기로 확정했는데 지형 도구는 이미
있었다. 코드에서 유도한 성질이므로 검사 항목으로 확인한다.

### 검증 3항목을 판정으로

0-1 BFS 를 두 번 돌린다. 한 번은 전부, 한 번은 착시 간선(`a.z !== b.z`)을 막고.

| 계획서의 질문 | 실제 판정 |
|---|---|
| 풀리는가 | `illusionCost !== null` |
| 배급량 안에서 풀리는가 | `illusionCost ≤ budget` |
| 최소 해법이 착시를 요구하는가 | `honestCost > budget` |

착시를 강제한다는 것은 **배급량을 `illusionCost` 와 `honestCost` 사이에
끼우는 것**이고, 그 구간이 비면 어떤 배급량으로도 안 되므로 지형을 다시
설계하라는 신호가 된다. 재설계 루프가 도는 자리가 여기다.

**불변식:** 고정 구조물은 `z > 0` 이면서 그릴 수 있는 어떤 기둥과도 3D
인접하지 않게 놓는다. 그래야 정직한 길이 `z=0` 평면뿐이 되어 `honestCost`
가 정확해진다. 안 지키면 플레이어가 자기 판을 올려 정직하게 붙는 경로가
생겨 판정이 거짓말을 한다.

### 실패 이유가 다음 수정을 지시한다

무작위 재추첨이면 절차적 생성이고, 이유가 방향을 정해야 에이전트다.

| 실패 | 이유 | 다음 수정 |
|---|---|---|
| `UNSOLVABLE` | 목표에 닿는 길이 없다 | 목표를 당기거나 구조물을 하나 더 |
| `OVER_BUDGET` | 배급이 최소 해법보다 적다 | 배급을 `illusionCost` 로 올린다 |
| `ILLUSION_UNUSED` | 정직한 길이 배급 안에 있다 | 배급을 `honestCost` 미만으로 조인다 |
| `NO_BUDGET_WINDOW` | 조일 구간이 없다 | 지형 재설계 |
| `ILLUSION_FORCED` | 정직 의도인데 착시가 강제된다 | 배급을 늘리거나 `zMax` 를 조인다 |
| `TOO_SHALLOW` | 최소 해법이 너무 짧다 | 목표를 밀어낸다 |

각 시도의 `{ 시도번호, 실패코드, 한 줄 이유, 다음 수정 }` 을 배열로 남긴다.
이 배열이 AI_LOG 6단계의 증거이자 제출물 4번의 중심이다.

**난수는 시드를 고정한다.** `Math.random` 을 쓰면 검증이 재현되지 않고
디렉터의 판단 기록도 확인할 수 없는 주장이 된다. 3단계에서 검증 스크립트를
저장소로 옮긴 것과 같은 이유다.

### 성향 → 손잡이

| 읽은 성향 | 근거 지표 | 맞서는 방법 | 쥐는 손잡이 |
|---|---|---|---|
| 늘 다리로 민다 | `inkSpent` ↑ `illusionSteps` ↓ | 잉크를 조여 착시를 강제 | `budget` ∈ (illusion, honest) |
| 착시만 노린다 | `illusionSteps / (illusion+real)` ↑ | 정렬이 불가능한 지형 | `zMax` → 0~1 |
| 망설인다 | `redraws` ↑ | **배급을 최소 해법에 바짝 조인다** | `budget` → `illusionCost` |

세 번째는 계획서에 대응 규칙이 없어 이번에 정했다. 환급률을 낮추는 안도
있었지만 망설이는 사람에게 가장 가혹한 손잡이라 층을 못 풀고 막힐 위험이
있다. 실험할 여지를 없애 한 번에 결정하게 만드는 쪽이 "그 사람이 피하는
것을 만든다" 에 정확히 맞고, 손잡이도 `budget` 하나로 끝난다.

`zMax` 를 조이면 착시 후보가 구조적으로 사라진다 — 3단계에서 "상한 자체가
디렉터의 세 번째 손잡이" 라고 적어 둔 것이 여기서 값을 한다.

### 결정한 것

| 결정 | 이유 |
|---|---|
| **솔버는 판 높이 조절을 탐색하지 않는다** | 디렉터가 고정 구조물을 이미 맞는 높이로 놓아 준다. 그리고 걷기만 해도 풀리므로 계산이 정확하고 "배급량 안에서 풀린다" 가 보장된다. 플레이어가 높이를 조절해 더 싸게 푸는 것은 막지 않는다 — 영리한 것이므로 |
| **1층은 고정, 2층부터 디렉터** | 성향 지표가 0인 상태에서는 읽을 것이 없다. 1층을 손으로 잡아 두면 그리기·걷기·높이 조절을 배우는 순서를 설계할 수 있고, 영상에서 "플레이어를 읽은 뒤 달라진다" 가 대비로 보인다 |
| **판단 기록은 콘솔 + AI_LOG, 화면엔 표시 없음** | 화면에 띄우면 플레이어가 자기가 읽히고 있다는 것을 알아 행동이 바뀌고, 그러면 읽은 성향이 성향이 아니게 된다. 모서리에 조작·진행을 두기로 한 뒤에도 이것만은 그대로다 — 「모서리에 두는 것」 참조 |

### 구조

계획한 셋에 둘이 늘었다. 성향 읽기를 디렉터에서 떼어 낸 것과, 층 전환 배선을
`main.js` 가 아니라 따로 둔 것이다.

```
src/stage.js     현재 층의 손잡이 { inkMax, zMax, refund, start, goal, fixtures }
                 파생값 zTop — 그 층에 실제로 있는 가장 높은 것
                 board 가 상수 대신 여기를 읽는다. 층 세우기 / 갈아 끼우기
src/solver.js    순수. 0-1 BFS 최소 잉크. 재는 것만 한다
src/director.js  순수. 층 후보 생성 → 검증 3항목 → 실패 이유 → 재설계 루프
src/profile.js   순수. 지표 → 성향 → 지시(intent, zMax, depth)
src/session.js   층 전환 배선. 무엇을 남기고 무엇을 지우는가
```

`solver.js` `director.js` `profile.js` 는 `path.js` 와 같은 규율을 지킨다 —
살아 있는 `board` 를 한 줄도 읽지 않는다. `path.js` 를 그렇게 만들어 둔 것이
여기서 회수된다.

**계획과 다른 것 하나.** 검증 3항목을 `solver.js` 가 아니라 `director.js` 에
두었다. 판정은 층의 의도와 `candidateCells` 를 알아야 하는데 solver 에 두면
solver → director → solver 로 순환한다. **솔버는 최소 잉크만 재고, 그 숫자로
무엇을 판단할지는 디렉터의 몫으로 남긴다.**

**`zMax` 가 겸하던 두 가지를 갈랐다.** 정직 층은 상한이 0 인데 그 위에 뜬
구조물이 있으므로, 겸한 채로 두면 `pickAt` 이 0 까지만 훑어 화면에는 보이는데
집을 수 없는 판이 된다.

```
zMax   플레이어가 올릴 수 있는 상한          손잡이. 정직 층은 0
zTop   그 층에 실제로 존재하는 가장 높은 것   pickAt · 카메라 · 휠 천장이 읽는다
```

**놓치기 쉬운 것은 구조로 없앴다.** 카메라 여유가 `zTop` 에서 파생되므로 층마다
값이 달라지는데, 다시 안 잡으면 이전 층의 여유로 그려 판 머리가 잘리고 잘린
것은 화면 밖이라 보이지도 않는다. 부르는 쪽이 창 크기를 들고 있어야 하는 것이
문제였으므로 `iso` 가 마지막 크기를 기억하게 하고 `refit()` 한 줄로 줄였다.
잊을 수 있는 인자를 없앤 것이지 잊지 말자고 적어 둔 것이 아니다.

바닥 크기(`GRID_W/H`)도 층 파라미터가 될 수 있지만(카메라가 이미 대응한다)
넣지 않았다. 손잡이 셋으로 충분히 돌았다.

## 조작 체계

**무엇을 눌렀는가가 무엇을 하는가를 정한다.** 수식 키를 쓰지 않는다.

| | 빈 바닥 | 판 위 |
|---|---|---|
| 좌클릭 / 드래그 | 그린다 | 그리로 걸어간다 |
| 우클릭 드래그 | (아무 일 없음) | 지운다 |
| 휠 | (아무 일 없음) | 높이를 올리고 내린다 |

수식 키(Shift, Ctrl)를 쓰면 버튼은 얼마든지 늘어나지만 아무도 발견할 수
없다. 모자란 것은 버튼이 아니라 **발견 가능한 입력**이다. 그래서 대상과 기본
입력의 조합만으로 구성했다.

그리기와 걷기는 대상이 정확히 배타적이라 충돌하지 않는다.
판 위에는 그릴 수 없고(점유 칸은 건너뛴다), 빈 바닥은 걸을 수 없다
("걷는 것은 눕힌 판 위에서만"). 우연이 아니라 게임 규칙에서 나온 결과다.

발견 순서도 규칙 안에 들어 있다. 처음에는 판이 하나도 없으므로
무조건 그리기부터 배우게 되고, 판이 생긴 뒤에야 그 위를 눌러볼 기회가
생긴다.

## 모서리에 두는 것

원래 원칙은 "튜토리얼 문구 없음, 대사 없음" 이었다. 그것을 세운 이유는
**플레이어가 스스로 배우게 두는 것**이었고, 바닥을 문지르면 선이 나오는
것까지는 지금도 그대로다.

그런데 발견에만 맡길 수 없는 것이 셋 있었다.

| | 왜 발견에 맡길 수 없나 |
|---|---|
| 판 위와 빈 바닥에서 좌클릭이 다른 일을 한다 | 눌러 보기 전에는 알 방법이 없다 |
| 휠이 높이를 바꾼다 | 판 위에서 굴려 보기 전에는 존재 자체가 안 보인다 |
| 층이 넘어가고 있다는 것 | 도면을 넘기는 연출만으로는 몇 장째인지 안 남는다 |

심사자가 링크를 열어 **한 번 보고 판단하는** 상황이다. 제출물 3번이 조작
설명을 따로 요구하기도 한다. 그래서 규칙을 이렇게 고쳐 세웠다.

> **도면 위에는 문구를 두지 않는다. 화면 모서리는 제도판이므로 거기에는 둔다.**

모서리 넷이 각각 하나씩 맡는다. 전부 청사진 팔레트 안에서만 쓰고, 앰버는
쓰지 않는다 — 잉크 게이지와 목표 표식의 색이라 다른 데 쓰면 "이것이 자원이다"
가 흐려진다(4단계에서 캐릭터 색을 고를 때 세운 규율).

| 자리 | 무엇 | 왜 거기 |
|---|---|---|
| 좌상단 | 조작 안내 — 마우스 그림 + `DRAW · WALK` / `ERASE` / `LIFT` | 처음 한 번 읽고 마는 것이라 시선이 먼저 가는 자리 |
| 우상단 | 층 번호 표제란 — `SHEET 01` | 도면 번호. 조작 안내의 2/3 크기 — 계속 눈에 남는 것이라 더 조용해야 한다 |
| 좌하단 | 잉크 게이지 | 2단계부터 있던 자리. 숫자 없이 길이로만 |
| 우하단 | 도면명 — `SETOUT` | 제도 규격에서 표제란이 있는 자리. 한 줄뿐이라 가장 작다 |

**여전히 안 두는 것**은 그대로다. 디렉터의 판단 기록은 콘솔과 `AI_LOG.md` 에만
남긴다 — 화면에 띄우면 플레이어가 자기가 읽히고 있다는 것을 알아 행동이
바뀌고, 그러면 읽은 성향이 성향이 아니게 된다. 착시인지 진짜 길인지도
표시하지 않는다. 그냥 이어져 보이기만 한다.

화면이 하는 말과 코드가 하는 일이 갈리지 않는 것은 검사가 지킨다
(`test/hud.test.mjs`) — 안내에 적힌 라벨을 그대로 꺼내 실제 `attachPointer` 에

## 보류한 것

| 보류 | 이유 | 다시 볼 시점 |
|---|---|---|
| 판 세우기 (벽) — **넣지 않기로 확정** | 눕힌 판을 올리는 것만으로 잇기와 가리기가 둘 다 나온다(대각선 옆은 잇고, 대각선 위는 덮는다). 기획서가 벽에 기대한 "어긋난 부분을 가려 이음매를 완성"은, 연결 규칙이 "화면상 정확히 한 칸 옆"이라 어긋남이 애매하게 남는 경우가 없어 할 일이 없다. 반면 넣으려면 발견 불가능한 입력을 만들어야 하고(튜토리얼 문구 없음 원칙과 충돌) 세운 판의 렌더·깊이 정렬·가림 판정을 새로 짜야 한다 | 마감 뒤 |
| 뜬 판 아래로 다른 판 통과 (2층 구조) | 판을 올려도 그 기둥은 계속 잡아 두기로 했다. 비워 주면 한 `(x,y)` 에 판이 여럿 겹쳐 `(x,y) → 판` 조회가 1:1 이 아니게 되고, 지우기·잉크 회계·연결 성분 분해가 전부 그 위에 서 있어 셋 다 다시 짜야 한다. 착시는 화면상 정렬로 성립하지 층 쌓기로 성립하지 않으므로 얻는 것도 없다 | 마감 뒤 |

## 막은 구멍 — 징검다리 이동 ✅

앞에 그리고 뒤를 지우며 전진하면 칸당 실질 비용이
`INK_COST - INK_REFUND` 로 떨어진다. 2단계에서 실측했을 때
직접 60칸 대 징검다리 110칸으로 1.8배 유리했다.

**환급률로는 막을 수 없다는 것이 계산으로 나온다.** `N` 칸 건너기에서
직접은 `2N`, 징검다리는 `2N − R(N−k)` 이므로 징검다리가 싸지 않으려면
`R(N−k) ≤ 0`, 즉 `R ≤ 0`. 조건을 **밟았는가/아닌가**로 갈라야 했다.

4단계에서 `INK_REFUND_STEPPED = 0` 으로 막았다. 실측 재측정:

```
직접 그리기            60칸
징검다리 (환급 있음)   119칸   ← 막기 전
징검다리 (환급 없음)    60칸   ← 지금
```

밟지 않은 판은 절반 환급을 그대로 받으므로 설계 실험은 여전히 공짜다.
`test/stepping.test.mjs` 가 이것을 지킨다.

## 미결정 사항

**스테이지 전환 연출은 정해졌다** — 도면을 넘긴다. 지금 장이 위로 빠지고 다음
장이 아래에서 올라오며, 바닥 격자는 안 움직인다. 매 층 똑같은 16×16 청사진이라
그것이 제도판이고 움직이는 것은 그 위에 그린 도면이다. 덕분에 두 층을 동시에
그릴 필요가 없고, 한 장이 나간 뒤 다음 장이 들어오는 사이의 빈 도면 한 박자가
글리치가 아니라 뜻이 된다 (`1d602cd`).

**헛디딜 여유도 정해졌다 — 4칸** (`3a7cfc8`). 시드 200개 × 의도 3종을 1~6 으로
재고 골랐다.

| margin | 창바닥 여유 | 지형폭 | 착시 강제 | `NO_BUDGET_WINDOW` | 평균 시도 |
|---|---|---|---|---|---|
| 2 | 2칸 | 8.0칸 | 100% | 4% | 3.2 |
| **4** | **4칸** | 8.0칸 | 100% | 16% | 3.5 |
| 6 | 6칸 | 10.0칸 | 100% | 36% | 4.4 |

**정하는 것은 창 바닥이다.** 배급은 `budgetWindow` 가 낸 창 안에서 고르는데
망설이는 사람은 `slack` 이 0 이라 바닥을 받고, 그 자리에서 실여유가 정확히 이
값이다. **가장 많이 헛디디는 사람이 가장 적은 여유를 받고 있었다.** 조이는
것과 한 번 헛디디면 못 끝내게 만드는 것은 다르다.

올리면 착시 강제가 약해질까 걱정했는데 방향이 틀렸다. `verify` 가 착시 층에
`honestCost > inkMax` 를 요구하므로 통과한 층은 정의상 강제되고, `margin` 이
하는 일은 그 배급을 **찾기 어렵게** 만드는 것뿐이다. 못 찾으면 지형을 다시
뽑는다 — 압박이 약해지는 것이 아니라 재설계가 는다.

6 은 안 골랐다. 지형폭 중앙값이 8 에서 10 으로 밀려 폭이 좁은 지형이 통째로
떨어져 나가고, 그러면 짧은 이음매 층이 사라져 층의 성격이 한쪽으로 쏠린다.

남은 미결은 하나다. 게임은 지금도 돌아가므로 병목은 아니다.

- **커밋을 한 번에 몰지 않고 조금씩 나눠 쌓는다.** 마감 직전 한 번에 올리면
  "AI가 한 방에 뽑았다"로 보인다. 커밋 로그는 사실상 다섯 번째 제출물이다.

- **좌표 변환은 눈으로 확인하지 않는다.** 틀려도 그럴듯해 보인다.
  `node test/run.mjs` 로 확인한다. 단계마다 검증 항목을 늘린다.
- **도면 위에는 문구를 두지 않는다. 대사도 없다.** 바닥을 문지르면 선이 나오는
  것으로 스스로 학습한다. 다만 화면 **네 모서리**는 제도판이지 도면이 아니므로
  거기에는 표시를 둔다 — 아래 「모서리에 두는 것」 참조.
- **아직 그리지 않은 것 = 선, 그린 것 = 면.** 이 대비가 화면의 전부다.
- **푸시 후 1분 기다렸다가 실제 링크를 열어 확인한 뒤 제출한다.** Pages 빌드는 즉시가 아니다.
