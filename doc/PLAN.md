## 3단계 — 판 높이 ✅

**왜 여기인가:** 높이가 생겨야 착시가 성립한다.
`z` 가 전부 0이면 화면상 겹침이 일어나지 않아 착시할 것이 없다.

- [x] **좌표 정리: `(x, y, z)` 는 바닥의 `(x−z, y−z)` 자리에 나타난다**
      → z 는 화면 세로로만 움직인다. 착시 후보는 같은 세로줄 위에만 있다
- [x] 화면 좌표로 판 집기 `pickAt` — 휠·지우기·하이라이트·그리기 차단이 공유
- [x] 판 위에서 휠 → 그 판의 높이 `z` 올리기 / 내리기
- [x] 휠 제스처가 잡은 판을 놓지 않기 (판이 커서 밑에서 빠져나가므로)
- [x] 장치별 휠 값 흡수 (픽셀 / 줄 / 페이지, 휠 마우스 / 트랙패드)
- [x] `z > 0` 상태에서 깊이 정렬 재검증 — 겹치는 칸 쌍에 동률이 없음을 증명·전수 확인
- [x] 카메라 상단 여유를 `Z_MAX` 에서 파생 (따로 두면 상한을 올릴 때 판 머리가 잘린다)
- [x] **높이 상한 8 / 하한 0 결정** — 상한은 디렉터의 세 번째 손잡이
- [x] **설계 결정: 판을 올려도 기둥은 놓지 않는다** (2층 구조 불가, 조회 유일성 확보)

## 4단계 — 캐릭터와 이동 ✅

**왜 여기인가:** 착시는 "이어져 보이면 건널 수 있다"는 규칙이다.
건널 주체가 없으면 착시를 확인할 방법이 없다.
그리고 여기서 만드는 BFS 가 6단계 AI 솔버로 그대로 재사용된다.

- [x] 캐릭터 렌더 (구체 + 기둥 + 타원 그림자, 다리 없음)
- [x] 캐릭터를 판 윗면에 세울 때 `PLATE_T` 오프셋 적용
- [x] **캐릭터 색을 코발트 `#2E6FB7` 로** — 흰색은 판 윗면과 명도가 붙어 묻혔다
- [x] 목표 표식 렌더 (앰버, 빈 바닥 칸)
- [x] 이동 그래프 — 화면상 인접. **진짜 인접 ⊂ 화면 인접**이 전수로 확인됨
- [x] 착시 길 판정 (`a.z !== b.z` 한 줄)
- [x] BFS 길찾기 (`src/path.js`, **순수 함수 — 전역 상태를 안 읽는다**)
- [x] 판 위를 누르면 그 칸으로 이동
- [x] **결정: 누른 칸이 목적지, 뗀 위치는 무시** (모드가 `pointerdown` 에서 확정됨)
- [x] **캐릭터가 밟은 판은 환급하지 않기** ← 징검다리 차단. 119칸 → 60칸
- [x] 이동 연출 — 화면 공간 보간 + 가감속
- [x] 캐릭터를 태운 채 판 높이 조절 (높이를 판에서 끌어오므로 공짜로 따라옴)
- [x] 밟고 선 칸은 지워지지 않음

## 5단계 — 착시 연결 ✅

**왜 여기인가:** 게임의 이름값. 여기가 붙어야 '퍼즐'이 된다.

**착시가 성립하는 조건.** A 가 바닥, B 를 `z` 만큼 올렸을 때
`u = xb−xa`, `v = yb−ya` 라 하면 `|u−z| + |v−z| = 1`. 정수해는 둘뿐이다.

| B 의 위치 | 높이 | 결과 |
|---|---|---|
| 대각선에서 한 칸 벗어난 자리 (`u = v±1`) | `z = min(u,v)` | 나란히 선다 → **잇는 축** |
| 대각선 위 (`u = v`) | `z = u` | 정확히 포개진다 → **덮는 축** |

- [x] **겹친 후보 중 실제로 보이는 것만 길로 치기** — `z` 최대 하나만 남긴다
- [x] `pickAt` 을 부르지 않고 같은 규칙을 스냅샷 위에 다시 세움 (순수성 유지)
- [x] 보이지 않는 칸은 목적지로 누를 수 없음 (`pointer.hit` 이 이미 `pickAt` 결과)
- [x] **캐릭터를 덮는 높이 조절 차단** — 덮이면 화면에서 사라진다
- [x] 성향 지표 수집 — `inkSpent` / `illusionSteps` / `redraws`
- [x] 게임 내 표시 없음 — 그냥 이어져 보이기만 한다
- [x] **세운 판(벽)은 넣지 않기로 확정** — 「보류한 것」 참조
- [x] `AI_LOG.md` 5단계 기록

## 조작 체계

**무엇을 눌렀는가가 무엇을 하는가를 정한다.** 수식 키를 쓰지 않는다.

| | 빈 바닥 | 판 위 |
|---|---|---|
| 좌클릭 / 드래그 | 그린다 | 그리로 걸어간다 |
| 우클릭 드래그 | (아무 일 없음) | 지운다 |
| 휠 | (아무 일 없음) | 높이를 올리고 내린다 |

수식 키(Shift, Ctrl)를 쓰면 버튼은 얼마든지 늘어나지만 아무도 발견할 수
없다. 튜토리얼 문구가 없으므로 모자란 것은 버튼이 아니라 **발견 가능한
입력**이다. 그래서 대상과 기본 입력의 조합만으로 구성했다.

그리기와 걷기는 대상이 정확히 배타적이라 충돌하지 않는다.
판 위에는 그릴 수 없고(점유 칸은 건너뛴다), 빈 바닥은 걸을 수 없다
("걷는 것은 눕힌 판 위에서만"). 우연이 아니라 게임 규칙에서 나온 결과다.

발견 순서도 규칙 안에 들어 있다. 처음에는 판이 하나도 없으므로
무조건 그리기부터 배우게 되고, 판이 생긴 뒤에야 그 위를 눌러볼 기회가
생긴다.

## 보류한 것

| 보류 | 이유 | 다시 볼 시점 |
|---|---|---|
| 판 세우기 (벽) — **넣지 않기로 확정** | 눕힌 판을 올리는 것만으로 잇기와 가리기가 둘 다 나온다(대각선 옆은 잇고, 대각선 위는 덮는다). 기획서가 벽에 기대한 "어긋난 부분을 가려 이음매를 완성"은, 연결 규칙이 "화면상 정확히 한 칸 옆"이라 어긋남이 애매하게 남는 경우가 없어 할 일이 없다. 반면 넣으려면 발견 불가능한 입력을 만들어야 하고(튜토리얼 문구 없음 원칙과 충돌) 세운 판의 렌더·깊이 정렬·가림 판정을 새로 짜야 한다 | 마감 뒤 |
| 뜬 판 아래로 다른 판 통과 (2층 구조) | 판을 올려도 그 기둥은 계속 잡아 두기로 했다. 비워 주면 한 `(x,y)` 에 판이 여럿 겹쳐 `(x,y) → 판` 조회가 1:1 이 아니게 되고, 지우기·잉크 회계·연결 성분 분해가 전부 그 위에 서 있어 셋 다 다시 짜야 한다. 착시는 화면상 정렬로 성립하지 층 쌓기로 성립하지 않으므로 얻는 것도 없다 | 마감 뒤 |

## 막은 구멍 — 징검다리 이동 ✅

앞에 그리고 뒤를 지우며 전진하면 칸당 실질 비용이
`INK_COST - INK_REFUND` 로 떨어진다. 2단계에서 실측했을 때
직접 60칸 대 징검다리 110칸으로 1.8배 유리했다.

**환급률로는 막을 수 없다는 것이 계산으로 나온다.** `N` 칸 건너기에서
직접은 `2N`, 징검다리는 `2N − R(N−k)` 이므로 징검다리가 싸지 않으려면
`R(N−k) ≤ 0`, 즉 `R ≤ 0`. 조건을 **밟았는가/아닌가**로 갈라야 했다.

4단계에서 `INK_REFUND_STEPPED = 0` 으로 막았다. 실측 재측정:

```
직접 그리기            60칸
징검다리 (환급 있음)   119칸   ← 막기 전
징검다리 (환급 없음)    60칸   ← 지금
```

밟지 않은 판은 절반 환급을 그대로 받으므로 설계 실험은 여전히 공짜다.
`test/stepping.test.mjs` 가 이것을 지킨다.

## 미결정 사항

코드보다 이쪽이 병목이다. 정해지지 않으면 그 단계는 시작할 수 없다.

| 결정할 것 | 왜 중요한가 | 필요한 시점 |
|---|---|---|
| 스테이지 전환 연출 | 층이 넘어가는 것을 어떻게 보여줄 것인가 | 6단계 |

## 지켜야 할 원칙

- **커밋을 한 번에 몰지 않고 조금씩 나눠 쌓는다.** 마감 직전 한 번에 올리면
  "AI가 한 방에 뽑았다"로 보인다. 커밋 로그는 사실상 다섯 번째 제출물이다.
- **`AI_LOG.md` 를 그 자리에서 쓴다.** 나중에 기억으로 복원하면 반드시 빈약해진다.
- **좌표 변환은 눈으로 확인하지 않는다.** 틀려도 그럴듯해 보인다.
  `node test/run.mjs` 로 확인한다. 단계마다 검증 항목을 늘린다.
- **튜토리얼 문구 없음, 대사 없음.** 바닥을 문지르면 선이 나오는 것으로 스스로 학습한다.
- **아직 그리지 않은 것 = 선, 그린 것 = 면.** 이 대비가 화면의 전부다.
- **푸시 후 1분 기다렸다가 실제 링크를 열어 확인한 뒤 제출한다.** Pages 빌드는 즉시가 아니다.
