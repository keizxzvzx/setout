# SETOUT

> 이어져 보인다면, 이어진 것이다.

잉크는 유한하고, 착시는 공짜인 등각 퍼즐 게임.

**▶ 바로 플레이 — https://keizxzvzx.github.io/setout/**

브라우저에서 링크만 열면 된다. 설치도 계정도 필요 없다.

건축에서 도면의 선을 실제 부지에 옮겨 긋는 작업을 `set out` 이라 부른다.
이 게임이 문자 그대로 그것이다.

---

## 무엇을 하는 게임인가

청사진 바닥 위에 서 있고, 저 멀리 닿을 수 없는 곳에 앰버색 표식이 하나 있다.
**그 표식에 올라서면 그 층이 끝난다.**

바닥을 문지르면 선이 나온다. 손을 떼면 그것이 철판이 되고, 그 위를 걸을 수
있다. 표식까지 다리를 놓으면 되는데 — **잉크가 모자란다.**

그래서 다른 길이 하나 더 있다.

등각 투영에서는 `(x+1, y+1)` 로 한 칸 가는 것과 `z` 를 한 칸 내리는 것이
화면에서 **완전히 같은 픽셀 이동**이다. 깊이 정보가 수학적으로 사라진다.
그래서 저 멀리 떨어진 판을 알맞은 높이로 들어 올리면, 3D 에서는 아무것도
닿아 있지 않은데 화면에서는 **바로 옆에 나란히 선다.**

이 게임은 그것을 길로 친다. 이어져 보이면 건너갈 수 있다.

```
그리는 것은 비싸다.  착시는 공짜다.
```

초보는 잉크를 다 써서 다리를 놓고, 익숙해지면 판을 절묘하게 놓고 눈속임으로
건넌다. 같은 층을 두 가지로 풀 수 있다.

## 조작

마우스만 쓴다. **무엇을 눌렀는가가 무엇을 하는가를 정한다** — Shift 나 Ctrl
같은 수식 키는 쓰지 않는다.

| | 빈 바닥에서 | 판 위에서 |
|---|---|---|
| **좌클릭 · 드래그** | 그린다 | 그리로 걸어간다 |
| **우클릭 드래그** | (아무 일 없음) | 지운다 |
| **휠** | (아무 일 없음) | 그 판의 높이를 올리고 내린다 |

`Esc` — 긋고 있던 획을 취소한다 (이미 확정된 판은 건드리지 않는다).

같은 버튼이 대상에 따라 다른 일을 하는데, 둘은 정확히 배타적이라 헷갈리지
않는다. **판 위에는 그릴 수 없고, 빈 바닥은 걸을 수 없다.**

## 화면

도면 위에는 문구를 두지 않는다. 화면 **네 모서리**는 제도판이므로 거기에만 둔다.

| 자리 | 무엇 |
|---|---|
| 좌상단 | 조작 안내 — `DRAW · WALK` / `ERASE` / `LIFT` |
| 우상단 | 층 번호 — `SHEET 01` |
| 좌하단 | 잉크 게이지 (숫자 없이 길이로만) |
| 우하단 | 도면명 — `SETOUT` |

잉크 게이지는 세 겹이다. 진한 쪽부터 **지금 쓸 수 있는 잉크**, **확정된 잉크**,
그리고 **지워서 되받을 수 있는 것까지**. 잘못 그은 다리를 걸어서 확인해 보면
그 순간 가장 바깥 끝이 짧아진다 — 밟은 칸은 환급이 없기 때문이다.

판의 색도 규칙을 말한다.

| 색 | 뜻 |
|---|---|
| 강철 | 내가 그은 판. 지우면 절반이 돌아온다 |
| 청사진 쪽으로 당긴 색 | 미리 깔려 있던 판. 지울 수 없다 |
| 빛이 죽은 강철 | 밟은 칸. 지울 수는 있지만 잉크가 안 돌아온다 |
| 점선 | 판을 들어 올려 비어 보이지만, 그 기둥은 아직 잡혀 있어 그릴 수 없는 자리 |

## 잉크

| | 값 |
|---|---|
| 한 칸 그리기 | 2 |
| 지우면 돌아오는 양 | 1 (절반) |
| **밟은 칸을 지우면** | **0** |

마지막 줄이 이 게임의 경제를 지탱한다. 전액 돌려주면 앞에 그리고 뒤를 지우며
전진하는 것이 언제나 더 싸져서, 최적 전략이 지루한 반복 조작이 된다. 밟지 않은
판은 그대로 절반이 돌아오므로 **설계 실험은 공짜고 회수만 비싸다.**

## 층이 넘어가면

표식에 올라서면 도면이 위로 빠지고 다음 장이 아래에서 올라온다. 바닥 격자는
움직이지 않는다 — 매 층 똑같은 청사진이라 그것이 제도판이고, 넘어가는 것은
그 위에 그린 도면이다.

되돌릴 수 없이 막히면 (남은 잉크로도, 지워서 되받을 수 있는 것을 전부 더해도
목표에 못 닿으면) **같은 층을 다시 뜬다.** 새 층을 내지 않는다.

## 1층 다음부터는 AI 디렉터가 낸다

> AI는 레벨을 만들지 않는다. 플레이어를 읽고, 그 사람이 피하는 것을 만든다.

1층은 손으로 잡아 둔 고정 배치다. 2층부터는 디렉터가 플레이어를 읽고 층을 낸다.

읽는 것은 셋 — 잉크를 얼마나 썼는가, 착시를 몇 번 건넜는가, 몇 번이나 지웠다
다시 그렸는가. 그리고 그 습관에 **맞서는** 층을 낸다.

| 읽은 성향 | 받게 되는 층 |
|---|---|
| 늘 다리로 밀어붙인다 | 배급을 조여 그리기만으로는 못 가게 |
| 착시만 노린다 | 높이 상한을 0 으로 — 올릴 판이 없으면 맞출 정렬도 없다 |
| 망설인다 | 배급을 최소 해법에 바짝 조인다 |

층을 낼 때마다 **생성 → 솔버 검증 → 실패 이유 판정 → 재설계** 루프를 돈다.
0-1 BFS 로 "배급량 이하의 칸을 그려서 목표에 닿는 방법이 있는가" 를 착시를
허용한 경우와 아닌 경우로 각각 재고, 배급을 그 두 값 사이에 끼운다. 구간이
비면 어떤 배급으로도 안 되므로 지형을 다시 뽑는다.

판단 기록은 콘솔에 남고 화면에는 표시하지 않는다. 읽히고 있다는 것을 알면
행동이 바뀌고, 그러면 읽은 성향이 성향이 아니게 되기 때문이다.

설계 판단과 그 판단 기록의 실물은 [`doc/AI_LOG.md`](doc/AI_LOG.md) 에 있다.

## 직접 돌려보려면

ES 모듈을 쓰므로 `index.html` 을 파일로 여는 것(`file://`)으로는 안 되고,
아무 정적 서버로든 띄워야 한다.

```bash
python -m http.server 8000
```

그리고 http://localhost:8000 을 연다. Python 이 없으면 `npx serve` 도 된다.
빌드 단계는 없다 — 소스가 그대로 실행된다.

## 검증

```bash
node test/run.mjs
```

18개 묶음이 좌표계·잉크 회계·깊이 정렬·착시 연결·솔버·디렉터를 확인한다.
외부 테스트 프레임워크를 쓰지 않는다 — 게임이 라이브러리를 하나도 안 쓰는데
검증만 의존성을 들이면 "설치 없이 실행" 이라는 전제가 흐려진다.

**좌표 변환은 눈으로 확인하지 않는다.** 틀려도 화면상 그럴듯해 보이고, 깊이
정렬은 겹치기 전까지 증상이 없으며, 잉크 회계는 한참 플레이해 봐야 어긋난 것이
드러난다.

## 만든 방법

순수 HTML + JavaScript + Canvas 2D. **외부 에셋도 라이브러리도 쓰지 않는다.**
이미지·사운드·폰트가 하나도 없고, 화면에 보이는 모든 것은 좌표 계산으로 그린다.
3D 엔진도 물리 엔진도 없다.

라이선스 문제를 피하려는 소극적 이유만은 아니다. 등각 투영에서 착시가
성립하려면 화면상 픽셀이 정확히 맞아떨어져야 하는데, 범용 엔진의 카메라와 깊이
버퍼는 오히려 그 정확도를 방해한다.

```
src/iso.js       등각 투영과 자동 축척 카메라
src/board.js     판 — 그은 획이 철판이 되는 곳
src/input.js     포인터와 휠
src/render.js    Canvas 2D 렌더
src/path.js      이동 그래프와 BFS (순수)
src/solver.js    최소 잉크 0-1 BFS (순수)
src/director.js  층 생성 → 검증 → 재설계 (순수)
src/profile.js   지표 → 성향 → 지시 (순수)
src/session.js   층 전환
```

뒤의 넷은 살아 있는 게임 상태를 한 줄도 읽지 않는다. 그래야 디렉터가 **아직
놓지도 않은 배치**에 대고 "이게 풀리는가" 를 물어볼 수 있다.
